仓库解剖 I · Narrative Forge 工作流

Narrative Forge：从表单到可播放项目

本章不按按钮顺序复述界面，而是沿真实调用链追踪一次创作：浏览器怎样建立第一个项目，梗概怎样变成模型请求，模型 JSON 怎样安装成镜头与引用，关键帧和视频怎样成为任务，最后又怎样变成试玩包或分集成片。

读完本章，你应该能回答

  • 互动影游与 AI 短剧共用哪些模块，又从哪一步开始分叉。
  • 模型返回的 key、项目内 id 与 storyNodeKey 分别解决什么问题。
  • 为什么“生成成功”不等于“项目已经落盘、素材已经可发布”。
  • 当前代码哪些行为来自原作者版本，哪些是公开 fork 状态，哪些只存在于本地修复。

二、总体结构：一个 Python 进程，两个运行世界

源码实现 Python 入口使用 ThreadingHTTPServer 和 SimpleHTTPRequestHandler 的子类：同一进程既从 static/ 提供工作台文件，也把 /api/* 路径交给路由表，再从 projects/ 提供已落盘素材。证据定位：app.py · DirectorHandler.do_GET()/do_POST()/serve_static()/serve_project_file()；backend/route_registry.py · API_ROUTES。

源码实现 浏览器端不是服务端模板应用；static/index.html 提供 DOM，static/dist/bundle.js 是由 static/src/main.js 等 ES 模块构建出的运行包。项目编辑状态主要在浏览器内存和 Web Storage 中，显式“保存项目”才把 JSON 写入服务端目录。证据定位：static/src/main.js · bootstrap()；static/src/project-model.js · saveProject()；static/src/project-io.js · persistProject()。

最重要的阅读结论

分析推论 Narrative Forge 是“浏览器编辑器 + 本地协调服务”，不是把项目全部保存在 Python 内存中的传统后端应用。调试时必须先判断故障发生在 DOM 装配、浏览器状态、API 路由、供应商协议、任务轮询还是文件落盘，不能把所有失败都叫成“按钮没反应”。

三、首次启动：按钮获得生命之前发生了什么

  1. 源码实现 Python 导入时只读取仓库根目录的 .env，并以 override=False 保留宿主机或部署平台已经设置的同名环境变量。证据定位：app.py · ROOT/load_root_environment()。
  2. 源码实现 本地默认绑定 127.0.0.1:8765；若端口被占用，会从起始端口起共试最多 20 个候选，也就是再试后续 19 个。平台设置了 PORT 时，若没有显式 DIRECTOR_HOST，主机默认改为 0.0.0.0；平台端口不会静默顺延。证据定位：app.py · DEFAULT_DIRECTOR_PORT/resolve_server_address()/create_http_server()/main()。
  3. 源码实现 浏览器加载 bundle 后，入口等到 DOM 可用再执行 bootstrap()；它先缓存 DOM 元素，再尝试从 localStorage 读项目，否则用当前表单建立 version 6 空项目。证据定位：static/src/main.js · bootstrap()；static/src/state.js · initElements()；static/src/project-model.js · loadProject()/normalizeProject()。
  4. 源码实现 项目就位后才把元数据写回表单、绑定事件、渲染当前模式，并设置 document.body.dataset.appReady = "true"；健康检查与供应商配置加载随后异步进行。证据定位：static/src/main.js · bootstrap()；static/src/events.js · bindEvents()；static/src/project-io.js · checkHealth()。

为什么旧版会出现“所有按钮都不工作”

源码实现 原作者快照在首次项目尚为 null 时，readMetaFromForm() 会进入角色卡和场景卡读取，而两处读取器先访问 project.meta；本地修复把它改为 project?.meta，使空项目建立可以继续完成。证据定位：git diff abebc29..a9513b5 -- static/src/project-model.js · readCharactersFromForm()/readSceneCardsFromForm()。

分析推论 这类异常发生在 bindEvents() 之前，所以视觉上会呈现“页面出来了，但所有控件像死掉”；它并不证明每个按钮的业务函数都未实现。

五、互动模式：从表单到完整分支树

项目表单→ 树规模校验→ POST /api/generate-story→ 模型 JSON→ key 转 scene id→ 编辑／树览／试玩

1. 提示契约由后端编译

源码实现 前端 generateStoryDraft() 发送项目字段、角色卡、场景卡、树深、分支数和每节点镜数；后端 build_story_payload() 再构造 system/user messages，要求模型返回一个从 startKey 开始的完整有向树。证据定位：static/src/draft.js · generateStoryDraft()；app.py · build_story_payload()/DirectorHandler.generate_story()。

源码实现 模型传输格式的每条 scenes[] 包含临时唯一 key、storyNodeKey、节点内镜号、标题、五档景别、时长、动作、对白、choices[].targetKey 与 nextKey；同一剧情节点前几镜线性相连，选择只放在该节点尾镜。证据定位：app.py · build_story_payload() 返回格式与约束文本。

2. 文本供应商只返回模型响应，业务安装在浏览器完成

源码实现 /api/generate-story 调用 OpenAI-compatible 的 chat/completions，把原始供应商 JSON 回给浏览器；浏览器从第一条 assistant message 中清除 think/围栏并提取首个 JSON 对象。证据定位：app.py · DirectorHandler.generate_story()/atlas_request()；static/src/utils.js · parseStoryJson()。

源码实现 installGeneratedStory() 拒绝空 scenes、超过 240 镜、重复 key 与不存在的选择目标；随后为每条模型记录创建新的 scene.id，建立 key → id 映射，并把 targetKey/nextKey 改写成项目内引用。证据定位：static/src/draft.js · installGeneratedStory()；static/src/project-model.js · createScene()。

源码实现 若表单要求每节点多镜，而模型返回记录数恰好等于预期剧情节点数，安装器便把它启发式地视为“每节点一条”，将 action 按句子扩成多镜，用 storyNodeKey 归组，只在尾镜保留对白与分支；它没有先验证每个剧情节点是否确实各被覆盖一次。若模型记录数恰好等于目标总镜数，则直接采用其多镜结构。证据定位：static/src/draft.js · expandInteractiveStoryScenes()/installGeneratedStory()。

3. 安装之后仍是一份可编辑图，而不是不可变模型输出

源码实现 编辑器允许改标题、景别、时长、动作、对白、下一镜、选择文案/影响/目标、角色与场景卡关联、参考镜头和两类提示词；“设为起点”“添加节点”“删除节点”也直接更新项目图。证据定位：static/src/render.js · renderEditor()/renderFlowEditor()/syncEditorToScene()；static/src/events.js · bindEvents()。

源码实现 分支检查验证起点、目标引用、从起点可达性和至少一个结局；遍历时，有选择就只沿选择走，否则沿 nextSceneId 走。证据定位：static/src/story-graph.js · validateStoryGraph()。

源码实现 试玩器优先播放本地视频，再退到远程视频、图片或无素材占位；有选择时显示选择按钮，无选择但有下一镜时显示“继续”，无二者时显示结局。节点内多镜还可在视频结束或图片计时结束后自动进入下一镜。证据定位：static/src/player.js · renderStoryPlayer()/shouldAutoContinueStory()。

月城案例 · 互动映射

把“阮星的手停在两个按钮之间”设为一个剧情节点的尾镜，两个选择可分别写成“恢复全城记忆”和“释放弟弟救生舱”，各自指向后续节点的首镜。若这个选择前需要“看核心—看弟弟—手伸向按钮”三镜，三条项目记录共享一个 storyNodeKey，前两镜只用 nextSceneId，第三镜才拥有选择。

六、短剧模式：从系列规划到当前集镜头列

项目与当前集表单→ 前端编译长提示→ POST /api/generate-episode→ 模型 JSON→ 当前集 scenes→ 衔接重建／线性播放

1. 分集是容器，生成范围是“当前集”

源码实现 进入短剧模式时至少创建一集；每集保存标题、梗概、目标、钩子、结尾和目标镜数，并拥有自己的 scenes、起点与当前选择。证据定位：static/src/mode.js · setMode()；static/src/episode-model.js · create()；static/src/episodes.js · syncEpisodeFromForm()。

源码实现 project.scenes 在短剧模式下是当前集 scenes 的访问门面，所以生成、编辑和拖动仍能复用原有镜头代码；切换选中集后，同一属性会指向另一个容器。证据定位：static/src/episode-model.js · activeContainer()/installFacade()。

2. 短剧提示由前端编译，后端只加 system message

源码实现 generateSerialDraft() 把项目标题、全剧梗概、类型/基调、角色卡、场景卡、视觉风格、本集五项元数据、上一集摘要和下一集标题拼成一个长提示，并要求严格数量的线性镜头 JSON。证据定位：static/src/draft.js · generateSerialDraft()/serialPrompt。

源码实现 提示要求模型先在内部拆连续节拍，但返回结构并没有 beat 数组；每镜返回 key、episodeOrder、标题、景别、时长、动作、对白、转场、入口/出口状态和 nextKey。证据定位：static/src/draft.js · generateSerialDraft() 的返回格式与要求 1–9。

源码实现 后端 generate_episode() 只校验提示、模型、Base URL 和密钥，加入“只返回 JSON”的 system message 后调用 chat/completions；它不重建短剧业务提示。证据定位：app.py · DirectorHandler.generate_episode()。

3. 安装器把模型记录变成可生成镜头

源码实现 installGeneratedSerial() 拒绝空 scenes、超过 200 镜与重复 key；它把景别限制在五档、转场限制在四类、时长限制在 4/6/8/10/12/15 秒，并把过长对白向上调整到可容纳的时长档。证据定位：static/src/draft.js · installGeneratedSerial()；static/src/utils.js · dialogueBudget()/recommendedDialogueDuration()。

源码实现 临时 key 被映射为新 scene ID；模型角色卡或场景卡若非空，会替换项目级对应数组。自动关联时，角色名匹配镜头标题、动作与对白，场景名只匹配标题与动作。证据定位：static/src/draft.js · installGeneratedSerial()；static/src/project-model.js · autoAssociateCards()。

源码实现 安装完成后，rebuildSerialTransitions() 为缺失的入口/出口状态做邻镜推断，并重新组合视频提示；线性播放器把所有集按集序和镜序摊平成一列，可手动前后翻或按视频结束/图片时长自动播放。证据定位：static/src/prompt.js · rebuildSerialTransitions()；static/src/player.js · serialOrderedScenes()/renderSerialPlayer()。

月城案例 · 短剧映射

章节 2 的八镜可放进一集：本集钩子是“月城将在 38 秒后断电”，目标是让阮星确认二选一规则，结尾是弟弟说“姐，让我选”。每镜的动作和对白进入 action/dialogue，道具、视线与姿势的交接进入 entryState/exitState，镜 01–08 用 nextSceneId 线性连接。

八、图片与视频：两段生成、一个统一任务外观

关键帧任务

源码实现 点击生成关键帧时，前端先同步编辑器，检查提示词与参考镜头，再按“参考镜头优先于角色卡图”的规则组装最多两类连续性参考；它发送尺寸、质量、格式、模型和供应商设置到 /api/generate-image。证据定位：static/src/api.js · generateImage()；static/src/utils.js · imageSizeForAspect()。

源码实现 后端只使用参考图数组的前四张，超出的会被忽略；有参考图时切换编辑模型，本地 /projects/ 图片会转成 data URI，再由所选 adapter 生成供应商请求。证据定位：app.py · validate_image_params()/resolve_reference_image()/DirectorHandler.generate_image()；backend/providers.py · 图像 adapter 的 submit_spec()。

图生视频任务

源码实现 视频生成必须先有当前镜头关键帧，并发送当前镜头视频提示、关键帧 URL、时长、分辨率、画幅、模型和供应商设置；对白超预算只提示风险，不阻止提交。证据定位：static/src/api.js · generateVideo()；static/src/utils.js · spokenCharacterCount()/dialogueBudget()。

源码实现 后端通用视频校验接受 1–15 秒整数、480p/720p 和三种画幅，再交给 AtlasCloud、Seedance 或 DashScope adapter；Seedance adapter 会把供应商时长夹在 4–15 秒。证据定位：app.py · validate_video_params()/DirectorHandler.generate_video()；backend/providers.py · SeedanceVideoAdapter.submit_spec()。

同步供应商与异步供应商为何看起来一样

源码实现 异步供应商返回真实任务 ID；同步图片供应商的结果被服务端缓存并包装成 sync-* token。前端统一保存 prediction ID，再轮询 /api/predictions/<id>；完成后读取第一条输出 URL。证据定位：app.py · DirectorHandler._submit_result()/api_prediction()；static/src/api.js · predictionId()/pollPrediction()。

源码实现 停止按钮只中止本地等待；若已经有 prediction ID，状态改为 paused，以后可继续轮询。完成的镜头图片/视频会尝试下载到 projects/<project>/assets/<scene-id>/，使用 .part 临时文件后原子替换。证据定位：static/src/api.js · stopTask()/resumeTask()/saveAsset()；app.py · DirectorHandler.save_asset()。

停止不等于取消计费

源码实现 媒体任务停止逻辑只 abort 浏览器请求，没有调用供应商取消接口；界面文案也明确提示供应商后台任务可能继续。证据定位：static/src/api.js · stopTask()/resetAsset()。

分析推论 因而批量生成的成本控制不能只依赖 UI 的“停止”；重写时应把“停止观察”“取消供应商任务”和“清除项目记录”建模成三个不同动作。

本章结论：它不是空壳，但它把很多创作层压进了镜头记录

分析推论 当前基线的按钮背后有完整的创建、文本生成、安装、人工编辑、分支检查、媒体任务、播放、保存与导出调用链；“所有按钮无反应”的根因属于首次 bootstrap 在事件绑定前中断，而不是按钮函数普遍缺失。

分析推论 同时，这条链并不等于完整的影视前期系统：它从项目/分集直接落到镜头，把场次任务、节拍认领、故事板面板、声音设计和生成版本等中间层压缩成自由文本或根本不保存。下一章将逐字段拆开这种便利与代价。
