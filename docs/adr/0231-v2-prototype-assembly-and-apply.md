# ADR 0231 — V2 prototype assembly and explicit Apply

Status: accepted for the owner-authorized Last Projection V2 prototype, 2026-11-01.

The V2 delivery consumes a frozen native export, hash-bound full takes and an
explicit expanded structural story. It is an immutable-export prototype assembly,
not a claim that the expanded graph has current native production approvals.
Continuous scenes preserve every full input frame, native audio and constituent
logical slot offsets. Source text, logical story identity and media identity are
recorded separately. Source-level generation-direction edits do not impersonate
an unchanged native revision. A new game/save identity preserves V1.

The production page lists completed native jobs as they arrive. Playback is
optional and changes no selection. Regenerate uses a fresh single-shot native
request even for a currently selected shot; it does not force rejection or
unselection. Optional source editing uses the ordinary shot-presentation amendment editor. New
video directions retain the pinned final-video skill and Quality 8.

The task-installed Apply extension prepares the whole actual package first,
checks exact current native sources and prior publication/selection identities,
and prepares a visible complete replacement proposal with exact job IDs and a
proposal hash. Apply freezes that declared list; a newer arriving candidate
cannot silently replace a declared descendant. A published child is retained
when its frozen START still matches the replacement's actual final PNG; only
affected descendants propagate. Missing descendants leave Apply pending. Selection and
the immutable PlayerExport inventory row commit in one native project command;
the live game resolves that committed row. No file pointer can advance ahead of
the selections. Stale versions, changed bytes, wrong sources, rejected or
unresolved jobs and assembly failures retain the prior package and selections.

This bounded Apply may adopt completed unselected candidates retained by the
ordinary batch cancel operation. Cancellation stops new dispatch; it does not
reject completed outputs. It writes an exact source-bound-selections receipt
through the native segment selection owner under the same transaction as the
prototype publication. Cancelled batches keep their truthful cancelled state.
No UNKNOWN reservation is altered and no generation authority is created.

Direction edits use the existing source-bound shot-presentation amendment owner.
A canonical storyboard edit on an installed bridge correctly invalidates native
source-cut provenance; the prototype does not weaken that guard.

Player progress stores logical shot/offset within an assembled scene. A media
replacement can remap that offset and clamp within a shorter take while keeping
the authored path, journal and completed-route/ending archive. Cross-Apply
qualification uses one stable local game origin. Public ZIPs use relative
assets; private build receipts retain jobs, references and byte identities.

This is scoped prototype qualification. No push, CI, production activation or
owner personal creative acceptance follows from this ADR.
