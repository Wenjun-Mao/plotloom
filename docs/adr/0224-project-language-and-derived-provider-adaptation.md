# ADR 0224: Project language and derived provider adaptation

Status: accepted by the owner, 2026-10-28; implementation in progress under the
[authorized language plan](../roadmap/2026-10-28-project-language-consistency.md).

Application UI language and creative language have different owners. This delivery
supplies Chinese application chrome and new creative work in `zh-CN` or `en-US`.
The project locale deterministically selects report locale `zh` or `en`; candidate
metadata cannot override it. A frozen language artifact includes language-policy
and timing-policy versions in existing request identity. UI presentation never
enters creative hashes. Existing authored material and immutable reports retain
their original bytes; explicit Brief apply invalidates dependent new work.

Readable creative descriptions are authoritative. F5 `cut.composition`, Cast
appearance and Art summaries/lighting/state descriptions own audience-facing
meaning. English provider instructions are derived technical projections bound to
those sources and settings. A production brief is a complete read projection of
existing source owners, never a second editable story. Unsupported or lossy
adaptation returns an actionable conflict to the source owner before dispatch.

Creator generation authorization and assistant translation verification are
different facts. A distinct native checking invocation compares the complete
candidate with original sources, including omissions, negation, identities,
positions, dialogue, visible text and sound roles. Exact source, adaptation,
settings, checking provenance and compiled request identities bind new authority;
changed inputs invalidate it. Assistant review never claims the creator personally
reviewed English, and neither check nor authorization accepts generated media.
Historical frozen jobs keep their original stated authority.
Passive retained-proof reading validates the original frozen representation and
its hashes; it does not recompute old identities from current timing or style
rules. Additive optional rule fields preserve recorded omission on serialization.
Known fixed original package plans remain inspectable without executing recorded
argv, admitting historical work or granting replay authority. New preparation,
checking and publication still require current contracts.
Existing selected playback also validates its original frozen installation,
selection and source-data integrity without reinterpreting them through newer
validator files, language artifacts or timing rules. Code-only rule changes do
not withdraw already ingested, selected media whose underlying story/assets and
recorded authority are unchanged. Actual source edits, changed selections, stale
material/approval and integrity failures still withdraw eligibility. This is a
passive use of existing media, not historical compilation, generation, replay or
a compatibility execution path; new generation retains current admission rules.
Public generation currentness remains strict. Existing selected-media/segment
eligibility is the playback fact; player consumers must not require generation
currentness as well. Submission, retry, editing and reselection keep their current
admission requirements.

All eight generated text stages also receive a bounded content-language review
before adoption. A separate native invocation uses the original creative stage
with an explicit `content-language-check` operation. Trusted code classifies the
complete string-field inventory and binds original source, candidate bytes,
locale, policy/classifier version and actual native attempt/receipt to a typed
pass/reject/uncertain judgment. Names, quotations and intentional foreign/literal
text require source support; technical English and stable identities are classified
separately. Heuristics and writer-supplied flags never certify prose language.

The first real Outline exposed valid upstream extension fields from the saved
settings/topology instructions. Trusted classification grants technical/identity
exemptions only to explicitly owned paths. Every other string is conservatively
authored prose and requires actual semantic pass/reject/uncertain coverage; an
unknown field cannot use not_applicable or create an exemption. This preserves the
upstream extensible output shape without trusting model-authored setting echoes.
Malformed inventory paths and incomplete/forged coverage still refuse.

Real checker/correction evidence further established that machine echoes need
explicit ownership. Outline may omit optional echoes. If present, `storyTopology`
must equal its complete frozen input; registered machine settings and source
metadata must equal their explicit input projections. Only those bound leaves gain
stable/exact-source roles. Route references must belong to the frozen topology;
optional route-local IDs are code-owned ordinal labels (`R01`, `R02`, …)
attached to valid frozen paths, never new graph authority. Readable route prose and all other unowned strings still
require semantic review. The primary typed validator rejects mismatched echoes
before checking. New Outline requests freeze `outline-input-echoes.json`; the
primary plan binds the checked Python wrapper and pinned Node renderer together.
Retained package verification preserves each original fixed plan representation
without granting replay authority. Primary/correction prompts require omission or exact copying,
never translation of machine values. Classification grants no new canon authority.

The first real branch checks exposed ambiguous source-span coordinates. Trusted
code freezes the canonical candidate/source leaf paths in the existing response
schema; model-selected sourceSpan paths are relative to the sources object,
without an envelope `$.sources` prefix. Candidate paths are relative to the
candidate object. The model owns semantic choices and spans; trusted code owns
path vocabulary, byte hashes and exact Unicode validation. No automatic path or
offset correction is permitted, and malformed retained replies remain failed.

The real Cast checkpoint required a full remaining-stage ownership audit. A small
request-aware field owner now governs mode-specific fixed image-style labels,
source-bound optional style/section echoes, and the three exact Script timing
selectors; it grants no exemption to whole notes or arbitrary ID-looking values.
Provider prompts across both Art lighting/state arrays remain technical, while
associated state labels and descriptions remain readable project-language prose.
New text-only candidates omit embedded sheetImage resource locators; generated
media retains its existing app-owned phase. Original direction metadata is an exact
source quotation, not translated creative prose. Registered echoes must be exact
before gaining roles; additional readable members cannot hide in metadata.

Primary prompts, frozen response shapes, trusted validators, classifier and final
receivers share these owners. New Art shapes require nonblank lighting/state
descriptions, including optional cross-array entries when supplied; retained
original package/plan bytes remain readable without granting historical execution.
Stable IDs embedded in otherwise readable notes may be exact source-literal
quotations with verified spans; they never exempt surrounding prose or become
invented proper names. New notes should use readable project-language terms rather
than unnecessary implementation jargon. Existing source/candidate hashes, exact
Unicode validation, independent semantic checking and correction provenance remain.

Real Art generation demonstrated that an English-only provider gate must preserve
explicitly intended foreign visible text. Technical directions remain English;
exact visible lettering and explicitly supported dialogue retain their source
bytes and roles. A source-bound provider-literal contract records exact candidate
and original-source paths, Unicode spans, text and visible/spoken role. Trusted code
checks binding integrity and applies English/name gates to an ephemeral residual
projection only; candidate, report and submitted provider bytes remain unchanged.
Quotation marks alone grant no exemption. Voice-design prompts do not gain dialogue
or visible-text injection authority; spoken dialogue stays in its existing channel.

The existing checker explicitly inventories original-source visible facts in both
languages, including same-language lettering that needs no language exception.
Passed literal facts/claims propagate through exact upstream artifacts and native
receipts. Multiple valid witnesses for the same source fact do not create multiple
physical lettering requirements. No fact is added retroactively to retained results.

Source equality proves provenance, not author intent or completeness. Reuse existing
independently established literal facts when available, and use the existing distinct
native checker to verify proposed occurrences, intended nonspoken/foreign role and
required literal preservation against the original author facts. Provider-technical
not_applicable coverage cannot silently accept new literal claims or their omission.
Missing, translated, altered, stale, overlapping or invented bindings and concealed
foreign instructions refuse. Retained failed/corrected outputs remain original; an
old language-only pass does not become provider-fidelity evidence. H3's existing typed
visible-text and dialogue compilation remains the downstream owner, followed by its
separate fidelity check and actual media inspection.

The primary prompts, schemas, deterministic binders, owned Cast/Art/F5 gates, render
checkups, receiving validators and checker evidence share this contract. F5's blanket
exclusion of arbitrary quoted text is retired for new work; only verified literal
spans and exact Script-owned dialogue may bypass the English residual gate. Optional
Art saved-Brief styleAuthority uses the same exact four-field owner as Cast; it is
never free authored metadata. Existing Art sectionUsage ownership remains intact.

A genuine semantic rejection is a successful checking invocation, not a forged
failure of the original drafting attempt. Existing typed correction lineage
records the exact checker reference and original completed candidate. Corrected
or manually edited generated candidates need a current check of their exact
bytes before adoption. Missing, failed, uncertain or UNKNOWN checking blocks
adoption safely; it does not authorize duplicate dispatch or rewrite creative
values. This reuses existing native packages, attempts, rows and corrective jobs,
with no new approval engine, queue or human checkpoint. Assistant semantic review
is evidence of AI judgment with limits, never personal creator review or creative
acceptance.

Trusted dialogue timing owns language-sensitive estimates independently of provider
cut capacity. The shared versioned policy is frozen in Script/F5 requests and
implemented within each independently copyable upstream skill boundary. Models
cannot choose a faster rate to satisfy admission. Estimates establish necessary
capacity bounds, not natural performance or lip-sync acceptance. Real bilingual
speech and playback evidence remain required by the plan.

The three bounded extractions are language policy, display labels versus authored
values, and dialogue timing versus provider limits. No general translation
service, provider registry, full English UI, old-story conversion or new acceptance
engine is introduced. New persisted defaults follow the project; Chinese UI
placeholders never become saved creative values.
