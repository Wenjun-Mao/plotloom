# Current native Alpha acceptance

`alpha_native_codex_three_story.v1` qualifies the current native Codex workbench
independently: three fixed Chinese stories × three repeats, nine current text
installations, and at least 60 of 72 operations accepted on their first attempt.
The eight operations are Outline, Branches, Characters, Art, Script, Storyboard,
Bridge Intent and Bridge Presentation. The production correction default remains
one, restricted to Outline/Characters/Art. The source requests `gpt-6.1-sol` with
`medium` effort; its alias does not establish stronger server weight identity.

This executable replaces the mandatory two-saved-profile Alpha runner. Historical
18-run/six-review and four-stage 30/36 receipts retain their original meanings.
They cannot pass this native gate. Optional protocol conformance remains a
separate workload and policy in `plotloom.conformance`.

Use a clean owning source checkout and its checked locked Python environment.
Native execution also needs the source-owned `services/creator_workbench`
installation, actual Codex CLI, existing file-store login and current validator
resources. Installed wheels import the CLI but cannot invent a source checkout.
Run the production sandbox validator/render plans and permission negative controls
before admission. Pass their retained JSON proof with the exact CLI SHA-256,
profile hash, checked Python environment hash, eleven validate/render pairs in
`validatorCommands`, and the import plus six denial results in `negativeControls`.
Fixture executables or metadata receipts cannot establish native success.

```sh
uv run --locked --no-sync python scripts/alpha_acceptance.py prepare \
  --campaign /absolute/private/disposable-installation \
  --codex /absolute/path/to/codex \
  --preflight-proof /absolute/path/to/actual-envelope-proof.json
uv run --locked --no-sync python scripts/alpha_acceptance.py run \
  --campaign /absolute/private/disposable-installation --sample story-01-repeat-01
```

`prepare` requires a fresh directory outside the checkout, freezes all nine
sample UUIDs and exact Brief bytes before creating any project, and records clean
Git/tree/submodule, actual CLI/profile/pins, checked interpreter and dependencies.
It uses a separate private supervisor with the observed production pool limits
4 total / 2 text / 2 image / 4 queued. It does not copy production namespace or
frozen comparison-pair grants. Every `run` refuses source/runtime/profile drift
and advances only the selected original identity. Existing outcomes are never
silently rerun. The service command owns `RuntimeConfig/compose`; core imports do
not depend on unpackaged service modules.

The prefix holds the ordinary production controller lease before the application
starts, uses its repository claim and exact command authority, and invokes the
existing text controller. It never calls the early or late image scheduler.
Success pauses durably at current Bridge installation, verifies all four heads,
and reads them through a fresh store and actual HTTP API before shutdown. All
native jobs, attempts, package/receipt hashes, installation bindings and failures
remain in private campaign evidence. UNKNOWN remains unresolved evidence; no
replacement dispatch or clearing follows from qualification. `cancel` uses the
production control operation for exactly the selected disposable sample. Normal
project deletion/abandonment guards remain authoritative; no campaign cleanup
bypasses them.

extra prose/secret-bearing fields are rejected. The existing thresholds remain:
no fatal contradiction, every score ≥3, each sample mean ≥3.5, and each dimension
median ≥4.

`qualify --campaign ... --review-receipt ...` recomputes the exact nine-sample and
three-review gates from closed receipts. Text success claims machine adoption
only. It creates no product Approval, human review, images, material handoff or
AV output. Source qualification, activation and owner acceptance are separate.
