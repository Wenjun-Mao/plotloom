# ADR 0100: Reviewed production presentation ownership

Status: accepted for the bounded unattended Stage 4 source gate, 2026-10-02.

## Problem

Raw F4 action prose combines physical performance, exact phone text and runtime
choice instructions. F5 frames additionally describe reserved compositing areas,
but there is no compositor. The bridge kept only a cut's first beat and image
preparation exposed mixed beat prose as active media direction. Source-map graph
compilation retains labels but drops the choice question. Fresh bridge preparation
also checked a newly derived F5 binding instead of the retained accepted binding,
allowing old F5 evidence to be paired with a newer Script.

## Decision

Keep accepted F4/F5 immutable review evidence. Before production installation,
require an explicitly reviewed whole presentation package. Trusted code owns
source IDs, coordinates, raw texts/hashes and the exact current SectionMap choice.
The reviewer partitions every source field into contiguous, exhaustive spans:
physical direction, diegetic visible text, runtime choice, or review-only direction
with a stated reason. The reviewer owns semantic faithfulness and rendering;
mechanical coverage does not certify that all story facts were preserved.
No regex or model silently classifies or deletes source prose.

Reviewed physical spans project canonical action/composition in source order.
Dialogue remains cue-owned; a dialogue-only cut may have empty physical action.
Diegetic words remain exact original-language, nonspoken text in a named canonical
field. Runtime question/labels remain source-bound and appear only after node
completion. Playback ownership derives from current media admitted by the
canonical playback manifest; retained stale or foreign-shot bridge jobs cannot
veto independent current canonical playback. The reviewed package and all raw evidence remain inspectable.
Visible text validation rejects blank text without normalizing any authored
characters. The H3 compiler alone places typed visible text in its nonspoken
role; source-bound package review owns semantic separation. Substring overlap
with ordinary physical English (for example a label "In" and camera "Push In")
cannot establish misuse and is not rejected. Existing dialogue duplication
guards remain unchanged. Image/H3 consume projected media fields, never raw mixed source prose; narrative
scene objectives/beat purposes remain review context outside active media input.
F5 h3Prompt stays evidence, never executable provider input. Neither reserved
areas nor correct prompts establish rendered text fidelity; actual media still
needs audiovisual review before selection. No compositor is introduced. New H3 jobs freeze compiler
`plotloom.h3-reviewed-frame.v5-presentation`; retained jobs dispatch their existing
stored prompt bytes and are not relabelled. New production image jobs freeze
`physical-visible-runtime.v1` and use pinned package version 5. Existing frozen
package projections remain byte-stable; new character/art proposals retain their
current package contract. Specialist provenance includes presentation, timing and
canonical schema owners.

Exact seconds-to-integer-ms conversion belongs at bridge/provenance boundaries:
reject bool, nonfinite/nonpositive values or fractional milliseconds without
rounding. Raw F5 review admission is unchanged. Production conflicts explain
unrepresentable cuts. Frame-grid eligibility, qualified request capacity,
segment-required consent, derivative and selection gates remain separate.
Bridge preparation checks the retained accepted F5 binding and frozen timing
policy before deriving/freezing source inputs; stale evidence cannot be laundered.

Frontend source handoff and readiness use the same decimal-value conversion,
including fractional seconds such as 2.5 and 1.001; binary multiplication cannot
decide exact millisecond representability. Browser projections also refuse units
outside their safe integer domain. Coordinates retain positive-integer validation.
The H3 request form and preparation summary share current 24 fps / 17k+5 ceiling
and source-frame/capacity calculations, including nonnegative remainder semantics.
Only a qualified H3 catalog supplies covering-request guidance; other providers
and unavailable catalogs do not inherit H3 admission. The existing disabled
capability projection identifies H3 through `enabled: false` and
`reason: h3_video_not_configured` when no adapter is configured; this permits
read-only catalog explanation, never configured-backend controls or dispatch.
An unrelated adapter or a generic duration list does not identify H3.
A covering request requires
segment review unless its frame count exactly matches the authored duration.
This replaces the obsolete six-second/eight-second display exception without
changing canonical timing, provider contracts or media selection authority.

Isolated H3 composition is explicit/default-off and shares the trusted H3-only
builder while RuntimeConfig exclusively owns isolated storage. Provider-only
`VideoProviderSettings` and full runtime settings share trusted dotenv loading
and exported-environment precedence. Isolated composition validates only provider
configuration; unrelated normal storage, obsolete storage settings or malformed
normal runtime fields cannot veto its valid explicit RuntimeConfig. Health capability
modes are unique nonblank strings requiring image/text; unconsumed extras do not
enable request modes. All other catalog and closed job-envelope checks remain.

## Alternatives and consequences

Changing only H3 action leaves image inputs exposed. Joining raw actions bakes
choice UI into media. Rewriting accepted scripts destroys retained provenance;
freeform English overrides lack coverage. Automatic text compositing is a larger,
unproven implementation and is not required if reviewed output is faithful.

Guardrails cover exhaustive source partitions, currentness/CAS, ordered multibeat
and dialogue-only projection, exact visible text, runtime choice rendering,
fractional timing provenance, isolated storage/default-off and capability grammar.
Existing evidence is not relabelled as satisfying this new contract. New bridge
proposals require new explicit presentation review; old proposals do not install
under this contract.

## Current-schema boundary — 2026-10-07 functional E2E

Current proposal creation always emits a presentation package, including pending
unassigned sources. A missing package is not a valid historical variant of the
current proposal: the proposal schema and stored-row readers require it. Removed
nullable/optional fields, missing-package reconstruction defaults and the UI's
historical-proposal branch. Missing whole proposal remains the legitimate
preparation state; incomplete presentation remains visible and blocks install.
No migration, owner-data rewrite or compatibility adapter is introduced. Tests
reject missing/null packages and retain current reviewed installation behavior.
