## Scope, cause and decision

The owner requested the original Storyboard report above the structured
candidate disclosure, more reading space, and a pop-out like the existing
report reader. Trusted starting revision: `b435d2e8` on clean `main`.
See the [approved scope](../roadmap/2026-10-11-storyboard-report-reading.md)
and [ADR 0126](../adr/0126-static-script-report-presentation.md).

The cause was host presentation: `StoryboardReviewPanel` placed its original
report after the structured readers, while `StaticReportReader` used the generic
320px-minimum iframe without enlargement. The report content itself was
already fully revealed and isolated. Fix the host's reading order, geometry
and dialog controls; do not rewrite the archive, grant its scripts permission
or change production/review semantics.

Storyboard now opts into the shared static reader's 72dvh inline preview and
existing 94dvh native modal. Script retains its existing non-expandable reading
layout. Both frames read the same frozen static URL through unchanged
`ProjectReportFrame` admission, empty sandbox and `no-referrer`. Native close
and Escape restore focus; changing the report URL or hiding the workflow closes
the dialog without focusing a hidden opener. Workflow guidance names the
original report and real enlargement button first; structured details remain.

Actual diff and dependency review found no changes to backend/API schemas,
request payloads, persistence, admission implementation, auth, provider/prompt
behavior, dependencies, build tooling or package contracts. The only new
navigation is an additional admitted read of the existing static report URL.
This qualifies for the repository's bounded local frontend policy, not a full
Python/release gate. No service restart or generation was performed.
