# ADR 0221: Backend contract and HTTP ownership

Status: implemented, independently reviewed, locally qualified by composite
evidence and activated with exact preservation/readback, 2026-10-26. Offline QA
does not imply owner creative acceptance.
Authority: [approved B1–B2 delivery](../roadmap/2026-10-25-b1-b2-backend-http-ownership.md).

The backend domain module forwarded unrelated canonical, Brief and timing models,
owned provider validation above named profiles, and mixed durable contract families.
The project-folder factory similarly mixed request admission, live error policy,
lifecycle, canonical drafts and review routes. An unused HTTP error registrar and
protocol/model forwarding module provided competing authorities.

Consumers now import each actual owner directly. `public_values` owns secret-free
name/value and HTTP(S)-root validation below both provider families;
`provider_snapshot` dispatches above legacy and named profile models. Stage,
project, run, exact-repair, evidence, artifact and media-task families have distinct
owners. Existing canonical, Brief, model-base, timing and media-draft owners remain
authoritative. There is no `domain` or API `models` compatibility barrel.

Storyboard dialogue and continuity helpers return immutable ordered observations.
The evaluator retains one gate-set version, complete input hash and ordered result
assembly, invoking continuity at its original positions. Gate IDs, required/advisory
meaning and technical-evidence authority are unchanged.

The factory composes explicit route registrars. Per-app request access owns its
ContextVar, inspection versus read/mutation admission, proof scope and handle
cleanup; app storage/readiness/credentials retain their existing lifetimes. One
live HTTP registrar preserves the factory's winning error policies, including
minimal revision-conflict bodies, bootstrap Retry-After and native FastAPI
validation. Standalone identity/graph safety fixtures use that same registrar.
Lifecycle, canonical/draft and authoring-review routes retain their order, CAS and
exact draft-consumption receipts. Review approval still uses delegated QA attribution.

Character-reference and ordinary image routes retain separate acceptance and
publication rules. Stateless package/output projections share byte/hash checks;
manual target naming lives with preparation. Both send paths retain configured
binding, exact package writing, lane reservation and synchronous persistence
revalidation before queueing, with the store alive through the callback. Stale
before-send authority refuses without queueing and releases only its unsent lane.
Cancellation and invalid delivery do not gain native-worker release authority.

G5's `text_provider_resolution.TextProviderResolver` is the sole resolver interface.
HTTP scheduler and profile-secret capabilities live in `api.protocols`; runtime
run-secret leasing stays distinct. Request headers, directory cursors, provider
views and approval projections have their actual HTTP owners. No schema/wire,
hash, lifecycle, provider, grant or production-adoption behavior changes.

The image source inventory already recursively covers API/persistence owners.
Nothing formerly pinned moves outside those roots; canonical models stay at their
pinned owner. The prospective image pin and native Python-tree identity change with
the code. The ADR 0184 purity tripwire was reviewed against unchanged secret-guard
AST; only its owner path changes from `domain.py` to `public_values.py`, producing
digest `8712c9cbf75e5dc4a5b6d10c91640c949ba7863320d11c206661c511559dc9c4`.
Frozen requests and historical receipts remain immutable.

Qualification, activation and creative acceptance are separate. This decision
authorizes no external generation, UNKNOWN clearing, live-project mutation,
provider/settings/grant changes, push or hosted CI.
