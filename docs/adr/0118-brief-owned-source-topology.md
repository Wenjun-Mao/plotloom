# ADR 0118: Brief owns the Source workflow topology

Accepted October 4, 2026 after the owner expanded the creator UI batch.

The Source map/consumer chain fixed one choice and two endings while Brief
controls specified a different graph. F1 bypassed choice-count validation for a
START branching node. Later cast/art/script bindings fixed three sections,
script route caps assumed opening+ending, and presentation/player admitted one
binary question. This is an owning-contract mismatch, not a missing Add option
button.

Plan a feasible frozen graph with the existing deterministic topology planner
before the model writes outline/branch prose. Brief owns decisions per complete
playthrough, distinct endings, total node budget, outgoing-option limit and join
count. Reject infeasible settings before dispatch with actionable Chinese
feedback; do not rewrite settings. START, DECISION, JOIN and ENDING have explicit
roles in new structures. Count actual viewer decision events and distinguish
options, complete playback routes and endings.

Use planner version `story_graph_topology.v2`: every new non-DECISION node has
one continuation successor (endings have none), and every structural branch is
an explicit DECISION with authored options. Version 1 could expand START or
SCENE through multiple continuations, making the player invent another choice
that was absent from the frozen decision count. Planning, skeleton receiving
checks and canonical graph validation now reject implicit continuation forks.
Retained binary START nodes use explicit CHOICE edges and remain readable.
Old frozen evidence is retained under its original version, never relabelled.

The branch model fills all planned node prose, every choice's question/options/
consequences and each join's narrative reconciliation. Trusted code owns exact
IDs, topology, structural parameters, frozen source/outline/map/Brief binding,
schema completeness and currentness. Store the topology with the accepted
source structure and compile it into the single canonical graph. It is review
input, never a second runtime route authority. Explicit draft adoption, map
confirmation and graph installation remain separate.

Generalize section consumers and script budgets to every graph node and complete
route. Freeze all current choice questions through production presentation and
admit the question for the currently playing node against the exact graph.
Requested joins share downstream content; no episode-to-node guessing occurs.

The Source receiving contract supports two through six options at a choice.
The planner search and both receiving schemas share that bound. The planner
uses a separate receiving-capacity constraint while preserving the original
Brief in the frozen structural parameters. Search for a feasible shape within
that capacity before rejecting preparation; an unrestricted minimum with too
many options is not proof of infeasibility. If no such shape fits, reject before
reserving or dispatching, explain the limit and retain the entered Brief.

Retained binary accepted maps and installed production are current valued assets,
not disposable development data. Keep their content/hashes and runtime reading
intact, with explicit retained-binary interpretation. New binary manual maps
must match their actual one-choice/two-ending structure; there is no silent
fallback from another Brief. General new suggestions always use the planned
structure. Structural edits stale the review chain and require new explicit
review; existing installed production cannot be replaced through this workflow.
Do not rewrite retained evidence or imply it met the new planner contract.

Rejected: adding dynamic form rows without trusted topology; fixing Source to
binary while retaining unrelated controls; automatically reshaping accepted
maps/production. Regression coverage includes multi-option decisions, multiple
choices per playthrough, shared endings/joins, infeasible requests, all-route
script caps, current-node choice admission, stale Brief and dirty drafts, and
hover/focus/tap help at narrow widths and reduced motion.
