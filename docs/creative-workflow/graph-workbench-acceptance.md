# 创作全生命周期验收 Playbook（含永久验收合同）

入口：每次重大更新或改动迭代，以本 Playbook 为基线填写当次运行配置，
执行 Create → Revise → Recover，再给出范围明确的验收结论。
它是可复用的操作与证据合同，不是某一次运行的完成记录。
工作流决定见 [ADR0127](../adr/0127-reusable-creator-lifecycle-acceptance.md)。
它把 v9 交互草图的 C01–C47、P01–P06 迁入当前 Plotloom 合同，并以 C48–C55
补足当前正式 UI 的逐控件操作覆盖。
功能正确与视觉清楚分别验证；断言通过、截图存在或审阅者报告不能替代实际观察。
每次完整 E2E 另做 E22 的全产品视觉与文案专门检查；功能演练中的顺带观察不能替代它。

## 一份 Playbook、当次配置、当次结果

- 本文件维护稳定步骤、C/P/E 编号、预期结果、旧缺陷回归和证据规则。
- 当前 roadmap 维护运行配置、批准范围、前置修复、具体 QA 项目与停止条件；
  同一范围更新原计划，不另建竞争清单或三个独立计划。
- 当次 verification ledger 维护实际执行、失败、修复、复查和未覆盖项。
  老结果保留为历史，不复制成新候选的 PASS。
- 不稳定洞见先记入当次结果；复现并审阅后，补入所属 C/P/E 子检查。
  只有产品合同正式退役才移除对应检查，并记录原因；不能为本次通过删除失败检查。

### 每次运行先填写的配置

| 配置 | 必填内容 |
|---|---|
| 改动与目标 | 本次改动、受影响 owner/流程、计划证明的结论与明确排除项 |
| 候选与环境 | 源码提交、checked static/轮包身份、实际加载的前后端、服务与桌面尺寸；混合版本不得当作同一候选 |
| 数据与保护 | 精确 disposable 项目/目录、已有故事和媒体基线、被保护项目与设置、允许的变更/删除范围 |
| 覆盖选择 | 各轮 C/P/E 子检查、执行方式、额外场景与原因；未覆盖必需项保持 NOT EXERCISED/PARTIAL |
| 权限与前置条件 | 原生生成、续跑、提交/部署、生命周期操作的现有权限；未解决能力与需要先修复的合同 |
| 执行与停止 | 一个 source/browser/data writer、独立审阅、有限生成规模、回调方式、停止条件与最终交接 |

配置可以调整重点、数据、执行顺序和原生生成规模，但不降低现有门禁。
已有明确的 specialist 协调授权包含同一运行内的常规跟进与安全续跑，
不因已修复的预检阻断重复索要批准；授权范围、真实停止与未知派发仍须区分。
见 [ADR0131](../adr/0131-routine-specialist-continuation-authority.md)。
例如纯展示变更可以不新增原生视频；结果必须明确它没有重新验证原生生成。
重大数据流、生成或投产合同变更需覆盖其创建、修改与恢复链，不能只查新建成功。
声称完整生命周期验收时，三轮所有必需子项都须有当前候选证据。

### 自动化保存边界

正常保存后重载、重启或外部修改上游的测试，先等待归属明确的成功写入 ACK，
再独立读回核对完整 payload / revision。click 返回、按钮 enabled 或服务器出现
某个值，都不能单独证明浏览器已收到 ACK。延迟 ACK、保存中切换和中断恢复
等故障场景是有意例外，仍按 Round 3 保留；不能统一加等待而吞掉这些覆盖。

## 三轮可复用操作

三轮共用一份配置和结果记录；稳定候选上的完整故事是后续修改基线。
已知未支持的能力先解决合同与实现，再验证；不能把正确拒绝当作修订完成。
具体能力限制与配置缺口由当次 roadmap 记录，不是本 Playbook 承诺已经支持。
实际调用前沿用下文的执行 pin 与派发安全要求。

### Round 1 — Create：完成可播放故事

1. 从 UI 创建最小可区分的分支故事，经来源、大纲、图审阅到角色/美术、剧本、分镜。
   当前来源、路线、角色、场次和镜头身份须可追踪；报告完整阅读、取消与再打开分别检查。
2. 原生执行角色、场景、道具图片，至少一组同主体候选比较；放大、来源/权利、
   明确参考选用和冻结输入读回分别检查。现有图片初态须说明来源，不能冒充本次生成。
3. 意图作者保存和模型生成分别记录；模型服务未配置不能得到生成 PASS。
   明确审阅并安装投产，检查每个带画面节点的场次/镜头和 route_only 边界。
4. 检查镜头批准、关键帧/末帧、取消、dirty 守卫和多镜头预览；有限 H3 准备/发送一次/
   等待/摄入后，原片、片段调整、预览与用于故事分别显式操作。
5. 实际播放所有完整路线与结局，观察镜头推进、选择、结束和缺媒体提示。
   记录剧情/角色/场次/镜头/参考/候选/选用的 revision、identity 与 hash，作为修改前基线。

映射：E01–E17，关联 C40–C44/C54/P01–P06。复杂结构与媒体规模分开选择，
不为计数生成全部组合；每个未覆盖组合有明确记录。

### Round 2 — Revise：修改已有故事并重新可播放

1. 基于已完成基线，逐项修改中间节点正文、插入节点、删除节点、增减选项和改接路线；
   同时覆盖 Creator/Pro 同源、预览/取消/Undo、保存/重开和身份不串写。
2. 修改已有角色的外观、形象风格/提示词及身份参考；角色增删和人物归属变更按当次
   批准能力明确列项，未支持的动作不能借 API 初态声称 UI 已可用。
3. 修改场景/道具参考或高层设置时，记录预期影响范围；比较草稿、已确认上游、
   剧本/分镜、投产绑定、审核、冻结任务和媒体选用，不仅查看 stale 标签。
4. 对每次改动列明：需重审/重建、仍可复用、需保留但不能作为当前内容使用的旧产物。
   无关正文、身份、文件与候选历史不得意外丢失；无关媒体继续可用须有当前绑定证据。
5. 通过受支持的修订/重建操作完成新候选、审阅和显式安装/选用，再播放全部新路线。
   声称只重建受影响内容时，比较实际任务和产物 identity/hash；阶段级重建也须如实记录。
   全新另建项目成功不能代替原项目修改后恢复成功。

映射：E05/E06/E07–E18，关联 C09–C36/C42/C48–C53/P01/P02。
角色、故事和参考改动各自检查，不能由一个结构改动代替全链路修订。

### Round 3 — Recover：困难状态与生命周期

1. 检查未完成正文/JSON、快速切换、双页签 stale、延迟 ACK、保存失败、离开/重开和
   实际 OS blur；确认作者缓冲与归属保留，没有重复写入或隐式确认。
2. 检查任务取消、已知失败、未知派发、等待期间导航及完成后刷新。
   注入故障与真实故障分开；不盲重发、不清租约、不重写冻结包、不重启 busy owner。
3. 在精确 disposable 媒体项目或明确标注的副本上检查快照/独立恢复、归档/取消归档、
   保存关闭、typed 删除取消/错误名/正确名；其他项目和配置不变。
4. 检查三至六个同层节点、长图、短桌面、详情中心钳制、分隔条、长中文/空值、
   帮助输入与键盘操作，以及当次尚缺的合法/非法节点类型、边种类、归属组合。
5. 进行 30–90 秒无预写结果的探索；保留失败截图，按根因修复并复查相邻状态，
   完成稳定候选独立审阅与发布门禁。可再次重开自己的干净示例，不重置作者项目。

映射：E19–E22，关联 C01–C08/C17–C39/C45–C55/P03/P04。
恢复 round 使用可恢复的具体测试对象；首次创建副本的方式同样注明 UI/API/operator。

## 当次记录与结论模板

每个子检查记录：round + C/P/E 编号、前置状态、控件/操作、预期可见结果、
实际结果、候选/产物身份、截图/读回路径、PASS / FAIL / NOT EXERCISED、
根因/修复/复查。不适用的条件仍留在范围表并写原因，不得标为 PASS。
软件自动门禁、当前 UI 功能/视觉、原生生成/播放、作者创意与媒体质量接受分别结论。
测试总数和截图数量不作为覆盖百分比；测试初态、fake/native、模拟/真实 OS 事件分别标识。
结束时列出未覆盖项、已知能力限制、精确 pending 任务、下一步和保护读回。
若必需原生功能或修订链尚未走通，结论保持 PARTIAL，即使软件已合格发布。

## 运行与证据

- 每个 C 和 P 项均 active，必须给出本次候选的证据；失败或未检查阻止交付。
- 使用仓库的 `uv`、Vitest、Playwright 和 release gates；见
  [开发指南](../development.md)。草图的 `verify-delivery.mjs` 不是生产验证入口。
- browser 指真实点击、输入、鼠标拖动、滚动和键盘；visual 指直接检查实际截图；
  pure 指合同检查；build 指当前构建；review 指独立审阅；readback 指状态读回。
- 记录源码和静态入口指纹、命令、终止结果、具体断言、观察和保留路径。
  修复后重跑受影响检查；最终 UI 候选必须重新跑全套门禁。
- 保留失败证据与根因。两次同项失败后重新评估方法，不能重复同一宽泛派单。
- 桌面矩阵为 1280×768、1280×460、1700×900。包含 viewport 截图；
  full-page 拼接图只补充内容观察，不能独立证明 sticky 控件的位置正确。
- 当前 Plotloom 只有既定深色主题；两种 OS 颜色偏好均应保持该主题可读。
  此检查不声称应用已提供浅色主题，也不为验收新增主题功能。
- 实际 OS blur 检查须确认测试浏览器没有焦点模拟，并记录前台应用、
  `document.hasFocus()`、可信事件、真实按住拖动及返回后的继续移动/释放。
  仅在测试自有页暂时关闭焦点模拟并在结束时恢复；合成 blur 只证明处理器。
  先等作者正文的明确保存 ACK，再断言取消缩放零写入；正常 blur 刷新作者草稿
  不属于缩放写入，也不能为零写入测试禁止保存或丢弃正文。
- 生成和媒体 QA 使用明确的测试自有目录与 fake transport，零真实 provider 调用。
  它验证软件行为，不能证明真实生成质量或作者接受。另行明确授权的真实功能演练
  按 E01–E22 记录；真实生成、代理测试选用和作者创意接受仍分别标识。

## 覆盖审计与实际试用

每次试用建立逐项记录：场景、精确控件和操作、预期可见结果、实际观察、截图或读回、
PASS / FAIL / NOT EXERCISED、根因、修复和复查。一个大项中的子控件和状态必须分别有记录；
不能用一个 happy-path 截图或总测试数宣布整项通过。

证据分为正常 8841 实际操作、隔离 fake 传输浏览器、模型/纯函数检查、真实创意与媒体接受。
API 或文件建立的测试初态明确标为 fixture；它不计作相应 UI 入口已经通过。
失败注入不计作真实后台故障处理已经发生；fake 交付不计作真实生成。
功能操作与直接视觉观察各自记录，未观察的状态保持 NOT EXERCISED。

先列出用户需求、当前可见控件及准备交付的声明，再映射到本清单。新发现的控件或状态
当次补入记录。至少包括两个非 happy-path 探索：不完整/混合连接和快速切换/未完成正文。
修复按根因所属层实施，保留失败截图，复查原始复现、相邻状态和受影响门禁。
没有实际走过所有必需子项时只能报告覆盖缺口，不能以“已完整试用”交付。

过去失败的固定回归入口：同排新增却落到下一排（C05/C09）、预览后续未建立（C11/C17）、
选项文字被读作第四个节点（C15）、详情落到图下（C03/C45）、改输入/改后续/删除找不到或
不可用（C18–C26）、取消后误以为故事丢失（P04）、报告无法再次打开（P04/C54）、
简报与分支容量脱节（P01/P02/C30）、故事与制作混淆（C40–C44）。

### E22 全产品视觉与文案专门检查

这是一项独立于功能通过的检查，复用当次 QA 数据，不为截图重新生成图片或视频。
分别记录视觉可读性、文案准确性及作者对创意和媒体质量的认可；本检查不评价画面艺术质量。

- **E22.1 视图清单：** 首页/项目列表、简报与设置、来源/大纲、创作/专业工作台、
  角色、美术、剧本、分镜/媒体、阅读/播放、运行轨迹/修复，以及各自的报告、对话框
  和设置面板。逐项登记当前入口，不能只查新工作台或只查正常页面。
- **E22.2 状态清单：** 各视图适用的空/有内容、选中/未选中、折叠/展开、hover/焦点、
  等待、失败、stale、dirty 与只读状态分别登记。真实运行与 fixture 状态标明；
  未出现的必需状态保留 NOT EXERCISED，不通过污染 owner 数据制造覆盖。
- **E22.3 桌面与阅读：** 1280×768、1280×460、1700×900 直接看 viewport 像素并实际滚动。
  检查层级、间距、对齐、控件/图标居中、尺寸、侧栏定位、必要操作可达、焦点和帮助。
  长中文、无断点标识和换行可读；参考比较不能裁掉辨认主体所需的内容。
  同时检查竖幅人物在缩略图、历史选择卡和冻结图片依据中的完整展示；主预览正常不能替代这些检查。
  不恢复 1024px 或手机支持/测试；full-page 图仅补充内容观察。
  警告区域内的表单也须检查：说明、单选项和动作不能被通用横向布局挤成窄列；
  H3 比例处理的三种选择在最矮桌面仍须完整可读、可选择，并保持默认拒绝与明确同意的语义。
- **E22.4 不自然措辞（weird wording）：** 检查生硬翻译、难懂术语、拗口句子、重复警告、
  中英混杂和缺少主语/作用对象的说明。普通创作者指导优先自然、具体的语言；
  专业诊断保留准确术语，但与主要操作说明分层，不能仅为“更顺口”削弱合同。
- **E22.5 语义与行动：** 路线/选项/节点、故事/制作、草稿/已确认内容等用词一致；
  项目目录读取失败不等于空目录；保留同筛选下的已知列表并暂停行操作，明确 GET 重试。
  追加失败按原游标重试，切换筛选不把旧列表当成新结果，关闭后迟到响应不生效；
  项目操作失败与目录读取失败分开。Source 读取失败在两种图模式中均可直接重读；
  初次图缺失不宣称保留内容，成功的规范只读视图不宣称读取失败。
  确认内容后的读取同样暂停新编辑/写入；读取失败不误报已成功的确认失败，
  精确回执核验后才重定 Undo 的绑定，迟到读取不覆盖新读取或较新保存回执。
  保存、准备、发送、检查、取消、确认、安装、选用、重开/重建说明与实际行为一致。
  读者应知道操作对象、结果、是否覆盖旧内容及下一步；不可把未支持或未来能力写成已可用。
  候选已准备不等于任务已发送；分别核对未发送、已排队、发送结果不确定与状态读取失败，
  标题不能越过实际发送状态作结论。读取错误展示具体原因，不显示 JavaScript `Error:` 前缀；
  重试读取不得变成发送，取消未发送候选后来源保留且重新准备入口可见。
  区分仅打开大纲修订与保存新来源：前者可以返回仍有效的旧大纲，后者只能阅读旧版本，
  不得指引用户执行已禁用的返回操作。核对旧大纲/分支保存不变、报告可重开、

## 每次重复的操作序列

未发布候选的隔离构建必须显式使用 Vite `--outDir` 指向准确测试目录，并核对正常服务
静态文件仍为已发布字节。`PLOTLOOM_STATIC_DIR` 只配置后端/测试夹具，不改变 Vite 输出。
默认构建会更新正常服务挂载的 `src/plotloom/static`，仅在已审阅候选正式发布时使用。
记录错误输出、恢复字节与实际暴露范围；不能把之后恢复说成从未改变。

真实 native 图像/H3 执行前先完成独立审阅与完整门禁，取得仅本地提交的明确授权，
