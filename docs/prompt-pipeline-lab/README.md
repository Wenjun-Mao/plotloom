# Narrative Forge 提示词与分镜生成图谱

这是一份独立、离线可读的交互式源码手册，专门解释 Narrative Forge 怎样把“页面默认值或用户输入”变成“分镜列表”。它追踪两条真实路径：

- 互动影游：前端发送结构化字段，后端组装 system/user prompt。
- AI 短剧：前端先组装完整的本集 user prompt，后端再添加 system prompt。

手册还单独解释文本模型响应怎样被抽取、清理、解析、校验、规范化、保存并渲染，以及分镜导入后关键帧/视频提示词怎样由确定性代码再次合成。

页面中的可切换 prompt 和响应均为绑定冻结提交的离线教学模拟；它会刻意展示源码里的契约瑕疵和宽松接收行为，但不会把教学 JSON、用户截图或保存后的项目样例冒充某次真实模型原始响应。

## 阅读

直接用浏览器打开 `index.html`。页面不请求网络，也不读取真实 API Key。

## 验证

需要 Node.js 18 或更高版本：

```sh
npm --prefix docs/prompt-pipeline-lab ci
npm --prefix docs/prompt-pipeline-lab run verify
```

验证器会检查页面内部链接、重复 ID、必要章节、脚本语法、历史源码证据地图覆盖和冻结版本标记。V1 源文件按独立仓库边界没有复制进 Plotloom，因此这里验证的是冻结研究产物的自洽性，不会假装重新审计缺席的源码；重新核验源码事实必须回到 `SOURCE_MAP.md` 指定的原始提交。视觉和交互仍应在真实浏览器中抽检。

## 证据边界

正文冻结在仓库提交 `24c3c47a6fb1e3fcd5a060d705f11bbffb9dbde9`。页面中的“实时组装”是对该提交中字符串模板的教学投影，不会调用模型，也不是生产代码的第二个入口。源码变化后必须重新审计并更新 `SOURCE_MAP.md`、页面版本标记和相应示例。

页面使用四类标签：

- `源码事实`：能直接定位到冻结提交中的实现。
- `页面默认`：来自 `static/index.html` 的初始表单值。
- `截图观察`：只来自用户提供的界面截图，不能证明提示词或模型原始输出。
- `分析提示`：对实现边界、风险或改写方向的解释。

## 范围

本手册只覆盖“输入到分镜列表”以及紧随其后的图像/视频提示词合成边界。它不实际调用第三方模型，也不评测某一模型的分镜质量。供应商密钥、部署认证和媒体生成协议仅在影响这条数据链时提及。
