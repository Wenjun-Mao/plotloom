03 · 响应实验室

同一份内容，在哪一关会通过或失败？

切换模型常见返回形态，再逐步观察 envelope、清洗、解析、安装和列表。

choices[0].message.content→ 删 think→ 删围栏→ 取首个平衡 {…}→ JSON.parse 一次
它不是 JSON 修理器

没有尾逗号修复、单引号转换、缺括号补全、schema 驱动重试，也不会把失败内容再发给 LLM。解析失败时旧分镜仍保留，用户可以重试或手工选择本地模板。

04 · Prompt 承诺 vs 代码执法

最值得理解的不是 prompt 写了什么，而是谁真的检查了它

生成契约

Prompt 要求

  • 严格等于 expected_nodes
  • 每个非结局节点恰好 branch_count 个选择
  • 指定深度的有向树
  • 最后一层没有选择
  • nextKey / targetKey 都必须有效
  • 每镜一个原子动作，最长 15 秒
自然语言≠程序断言
接收契约

安装器强制

  • scenes 是非空数组，且不超过上限
  • scene key 不重复
  • choice.targetKey 非空且存在
  • 镜别、时长、transition 走白名单
  • 文本截断并转为字符串
  • 无效 nextKey 静默变成结局

范围说明 本节的“安装器强制”和下方树形矩阵特指互动影游导入器；AI 短剧的差异在“响应字段如何变成内部对象”中单列。

截图观察 可见标签的文字转述

深度 3 × 二分支的满树
1 + 2 + 4 = 7

截图却呈现4 个带选择节点 + 3 个结局。仅凭列表无法知道它是汇合、环、不可达节点还是标签/连接问题，但它与 prompt 描述的“完整二叉树”不一致。

分析提示 这恰好说明：安装器只验证 choice 目标存在，并不验证完整树深、每层节点数、无汇合、无环和四个结局。

07 · 信息损失漏斗

项目保存的是“安装结果”，不是一次可复盘的模型运行

调用前system + user prompt

模板版本、输入字段与供应商参数没有随项目归档。

供应商原始 envelope

模型 ID、usage、finish_reason 与运行 ID 不保存。

解析前assistant 原文

think、围栏、前后解释和清洗差异不会保留。

安装时临时 key 与回退

key 被换成内部 ID；哪些值被截断或回退没有安装报告。

最终留下project.scenes

规范化镜头、卡片关联与派生媒体 prompt 进入本地项目。

分析提示 如果以后要重写系统，最先值得补的是 provenance：保存 prompt recipe/version、输入快照、原始 content、解析警告、字段回退和 key→ID 映射，而不是只保存最终列表。

08 · 不经过 LLM 的对照组

“本地模板生成”不是备用模型，而是另一套确定性作者

Σlevel 0…2 2level×每节点 1 镜→7 个分镜

互动模板按层循环创建标题、动作、对白和 choices；短剧模板按目标镜头数循环创建“开场钩子—人物反应—冲突推进—高潮反转—结尾悬念”等节拍。

它不先生成本地草案再交给 LLM，也不会在 LLM 失败时自动触发。失败提示只建议用户手工点击本地模板按钮。

09 · 如果你准备改写或重做

从契约入手，而不是只在 prompt 里加一句“务必严格”

  1. 01

    先定义唯一的 StoryboardResponse Schema

    明确互动与短剧共用字段、模式专用字段、枚举、长度、连接规则和版本号；让 prompt 示例、后端 structured output、前端安装器和测试共同消费它。

  2. 02

    把 prompt 所有权集中到可测试模块

    当前互动在 Python、短剧在浏览器。若不打算保留这种架构差异，应把两者迁到同一 prompt builder 层，并用快照测试固定每个变量的来源。

  3. 03

    先验证，再修改项目状态

    检查精确镜数、树深、分支度、无环、可达性、结局数、storyNodeKey/shotInNode 一致性和 nextKey；对修复策略做显式选择，而不是静默把无效 nextKey 变成结局。

  4. 04

    保留原始响应、清洗结果与安装报告

    将 provenance 与项目主数据分开保存：模型、prompt 版本、原始 content、解析警告、被回退字段和最终映射。这样才能解释某张卡为什么变成现在这样。

  5. 05

    把“生成”与“修订”分成两种操作

    生成可以替换整个作用域；修订则必须把当前 scenes、用户锁定字段和差异指令纳入上下文，并产生可审阅 patch，而不是默默重写。

  6. 06

    补齐真实回归测试

    至少覆盖完整 prompt 快照、think/fence 清洗、畸形 JSON、重复 key、无效 target/next、数量偏差、多镜 fallback、短剧时长调整，以及从响应到列表 UI 的端到端路径。

当前版本值得先记下的四个实现细节

  • 互动多镜确认框会重复乘镜数。只影响二次确认文案，后端 expected_nodes 仍按正确公式计算。
  • 干净启动的隐藏“林默”文本不是结构化角色卡。互动请求仍发送兼容 character；短剧 prompt 却会写“暂无角色卡”。
  • 现有分镜不会成为重新生成上下文。手工修改过的 action、dialogue 和顺序不会发给故事 LLM。
  • 后端成功不等于内容成功。传输重试只处理网络/HTTP；JSON 或故事契约错误留给前端一次解析。
