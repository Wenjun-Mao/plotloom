# ADR 0169: Isolated Codex Python validator runtime

## Context

The native Branches validator could not canonicalize the existing `.venv`
interpreter through the uv-managed Python alias under its exact sandbox reads.
The `20261014-07` diagnostic confirmed a copies-based environment and offline
checked-lock sync remained alias-free, with original-alias, sibling-runtime and
credential sentinels denied. Its import control then failed on
`src`: `PYTHONPATH=source/src` needs that directory, while the profile granted
only `src/plotloom`. Branches validation did not run. These failures belong to
the source-owned runtime/resource contract, before process admission.

## Decision

Fresh profile v7 supersedes ADR 0165's existing-`.venv` and alias-chain runtime
clauses. One environment at `.local/codex-exec/python-env` belongs to the exact
checkout. An explicit provisioning command creates it using a physical
versioned interpreter, `venv --copies --without-pip`, then the existing checked
lock with offline `uv sync --locked --no-install-project`. It uses copied
dependency files; it never imports the old environment's site-packages.
Provisioning is separate from readiness, admission and attempts. An existing,
missing, partial or changed environment is not repaired automatically.

The provisioning receipt binds the checkout path, interpreter bytes/version,
`pyvenv.cfg`, exact versioned base runtime, project/lock bytes and complete
installed dependency inventory. Readiness, profile hashes and Python stage
resources revalidate those identities. Drift makes fresh execution unavailable.
The base runtime may contain only confined internal aliases; the environment
interpreter and every ancestor to its versioned runtime must be alias-free.
Attempt processes use `UV_PROJECT_ENVIRONMENT` for this exact environment and
retain the frozen `uv run --project … --locked --no-sync` validation plans.
`UV_PYTHON` names the same physical base interpreter, avoiding ambient version
selection. Download and config discovery are disabled. A global
`--no-managed-python` preference is not a confinement control: uv 0.12.19
[rejects a discovered environment with a managed base under that preference](https://github.com/astral-sh/uv/blob/0.12.19/crates/uv/src/commands/project/mod.rs#L944),
then replaces it even when an explicit physical base request is accepted.
The checked environment identity and narrow reads provide the boundary.

Only Python-backed stages receive read access to `src`, after checking that its
sole child is the real `plotloom` tree, containing no symlink, special file or
hardlink to outside content. Source, dependency and base-runtime bytes are
pinned; generated bytecode is excluded from those hashes. Validator cache
lookup names a host-owned regular file outside the CLI's writable paths, so
it cannot resolve a bytecode directory; bytecode writing is also disabled.
Using writable CLI temporary storage would allow the model to seed validator
bytecode and is rejected. No checkout-root, shared Python parent or sibling-runtime read is
granted. Node stages retain their stage-specific resources and OpenSSL/temp
contract. Authentication, networking, source writes and unknown-outcome fences
remain under ADR 0165.

## Alternatives and consequences

Direct Python invocation would change the approved checked-lock `uv` plan.
Broad parent reads would expose unrelated content. Rewriting symlinks, injecting
old site-packages, or provisioning during an attempt would hide drift and create
unowned mutation. Those alternatives are rejected.

The environment is local setup state and is not portable project evidence.
Retained profiles/attempts remain read-only evidence under their original
contracts. Fresh execution requires a new profile and qualified source state.
Focused regressions cover missing and changed identities, aliases, unexpected
`src` siblings, symlink escape and unchanged Node boundaries. One separately
allocated native preflight must prove all eleven validator/render plans and
negative controls before any provider canary; successful import alone is not
qualification.
