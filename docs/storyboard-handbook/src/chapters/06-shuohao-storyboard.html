源码解剖 · novel-storyboard 1.3.0 · 固定提交 4322897

shuohao storyboard：从剧本位置到 H3 投产包

这一层不是一张传统故事板图片，而是一套“剧本节拍认领合同”：先把一集拆成视频生成段，再在段内切镜，为每切准备关键帧，为每段准备时间对齐的 H3 提示词，最后用 17 道门检查结构。

本章会彻底拆开

  • script.flow、sceneIndex、art sceneId 为什么是三套不同坐标。
  • seedScenes → segment → cut → beats/frame/h3Prompt 的完整变换。
  • 17 道质量门究竟查什么，哪些门缺上游时会跳过。
  • 关键帧、H3 投产包与真实视频生成之间的明确边界。
  • 29 秒“月城控制室”如何落进 3 段、8 切，以及这套模型会损失什么。

一、先确定现行模型：以 segment → cut 为准

文档声明 根 README、storyboard schema 和 SKILL 后半部描述的是三层结构：集（episode）→ 生成段（segment）→ 分镜切（cut）。段对应一次计划中的视频生成调用，cut 是段内的剪切，关键帧按 cut 准备。

源码实现 validateStoryboard() 要求每集有 segments，每段有 sceneIndex、cuts 和 h3Prompt；gateReport() 对段总时长、cut 时长和段内 H3 切点分别检查。源码没有现行的顶层 shots 数组。

测试约束 selftest 明确断言样例为 10 个 segment、34 个 cut、17 道门；seed 结果被断言为 segments.length === 0，而非 shots。

同一份 SKILL 里保留着上一版词汇

文档声明 SKILL 开头一张旧表还写“单镜头 ≤15 秒”“首帧 + 运动双提示词”和“每镜一段 H3”，Step 1 也写“shots 留空”。这些说法与同文件后文、schema、样例及源码不一致。

分析推论 学习当前实现时，应把它们视为文档漂移，而不是同时存在的另一套合法格式。现行合同是：segment 受 maxSegmentSeconds 约束（默认 15 秒），cut 受 minCutSeconds..maxCutSeconds 约束（默认 2–5 秒），每 cut 一个 frame，每 segment 一个 h3Prompt；顶层 params 可以覆盖这些时长默认值。

核对入口：skills/novel-storyboard/SKILL.md 第 44–58、74–107 行；references/schema.md；scripts/novel-storyboard.mjs::validateStoryboard()、gateReport()；scripts/selftest.mjs 的 stats、17 门与 seed 断言。

三、seedScenes：先把剧本变成可切的工作底稿

源码实现 expandScript() 遍历每集、每场、每个 flow beat：动作拍按剧本参数 actionSeconds 计时，默认 2.5 秒；台词去掉空白后按字符数除以 charsPerSecond，默认 4.5 字/秒，并四舍五入到一位小数。它还保留说话人、语气、文本、场景人物与道具。

源码实现 seedFromScript() 把展开结果写入临时 seedScenes，同时把最终 segments 留空。它可按 --eps 过滤集数。代理切完后，SKILL 要求删除 seedScenes，因为正式 storyboard 可随时从 script 重算底稿。

{
  "source": "月城失物局",
  "episodes": [
    {
      "ep": 1,
      "segments": [],
      "seedScenes": [
        {
          "sceneIndex": 1,
          "sceneId": "S01",
          "lighting": "日出前警报",
          "characters": ["C01", "C02"],
          "props": ["P01"],
          "beats": [
            { "n": 1, "kind": "action", "seconds": 2.5, "text": "阮星冲入控制室。" },
            { "n": 2, "kind": "line", "seconds": 1.6, "speaker": "VO", "text": "别让全城忘记。" }
          ]
        }
      ]
    }
  ]
}

这是符合 seedFromScript() 输出形状的教学缩略例；segments 尚空，因此它是工作底稿而非可通过最终 validate 的 storyboard。台词 1.6 秒只是按默认计数公式的示意，真实值由原字符串与参数确定。

script.flow → expandScript() → seedScenes → 代理切 segment / cut → 删除 seedScenes → validate

测试约束 selftest 断言 seed 保留六集、第一集两场、第一场全部 13 拍且每拍有秒数；同时断言 segments 为空，并验证集数区间过滤。

核对入口：novel-storyboard.mjs::expandScript()、seedFromScript()；references/storyboard-pass.md 第 1–18 行；scripts/selftest.mjs 的 expandScript 与 seed 小节。

四、正式 storyboard 的每一层存什么

表 2　episode → segment → cut 的字段责任
层级/字段 意义 是否派生或受门约束
顶层 source 剧名；结构校验必填。 直接存储。
style realistic 或 ghibli；默认 realistic。 每个 frame 必须含该预设的英文风格短语。
promptLang H3 正文和骨架语言；源码默认 en，可设 zh。 影响对齐句、字段名、镜头标记、姓名禁用与 H3 语言门；不改变 frame 恒为英文。
episodes[].ep 正整数集号；同文件不许重复。 必须能在 script 找到，段号前缀也由它决定。
segment.id E01-01 形状，集内从 01 顺序连号。 同时成为投产目录名；由段号门检查。
segment.sceneIndex 剧本该集第几场，1 起；一个 segment 不跨场。 通过 script 反查 sceneId、光照、合法人物、合法道具与 flow。
segment.cuts 段内按时间顺序排列的切。 段总时长不单存，始终等于 cut 秒数求和。
segment.h3Prompt 这一整段的一条 H3 视频提示词，包含所有 cut、声景和配乐。 首行、切点、台词、运镜和语言受多道门逐项对账。
cut.beats 闭区间 [start,end]，认领同一场的连续 flow 位置。 每拍必须恰好被一个 cut、按顺序、无缝认领。
cut.seconds 这一切的下单时长，不是剧本估时。 默认 2–5 秒；必须容得下所认领台词的估算秒数。
size / camera 五档景别与 H3 运镜词表中的一个动作。 景别英文短语进 frame；运镜词进自己对应的 H3 Shot 段落。
characters / props 当前关键帧画内的 C/P 资产。 必须是剧本该场集合的子集；人物超阈值需 note。
frame 这一切关键帧的英文图像提示词；不是图片本身。 必填、禁 CJK、含景别与统一风格短语、可选禁人名对账。
recipe 可选的 cut 级镜头配方卡 ID。 第 17 门始终返回；未挂库时以“跳过（视为通过）”记录，挂载 --shots 卡目录后才执行实质配方检查。

文档定义 references/schema.md。源码实现 DEFAULT_PARAMS、SHOT_SIZES、CAMERA_MOVES、STYLE_PRESETS、validateStoryboard() 与 gateReport()。

promptLang 的默认值有一处文档自相矛盾

文档声明 schema 顶部第 19 行明确写默认 en，但同文件 segment 表第 28 行又把 h3Prompt 说成“正文默认中文”。

源码实现 gateReport() 使用 board.promptLang ?? 'en'，H3_TOKENS 和测试的默认调用也都以英文为准。当前行为因此是：未写 promptLang 时默认英文。

五、默认参数是生产假设，不是电影学真理

maxSegmentSeconds = 15

一次视频生成段的上限；段内 cut 秒数求和不得超过它。

minCutSeconds = 2

单切下限；用于避免注意力节奏过碎。

maxCutSeconds = 5

单切上限；文档建议围绕约三秒变化。

maxOnScreen = 3

画内人物超过三人不是绝对禁止，但必须给 cut 或 segment 写拆解说明。

tolerance = 0.15

整集 storyboard 总时长相对 script 目标秒数的默认容差。

源码实现 默认值集中在 DEFAULT_PARAMS，paramsOf() 用 JSON 顶层 params 浅覆盖。cut 可以改上下限，段可以按目标视频模型改上限；代码不把 15/2/5 写死在门逻辑里。

文档声明 storyboard-pass 另外建议段通常 9–15 秒、3–5 切、固定镜头优先、一段内运镜克制。这些属于创作启发，不是全部由质量门强制的规则。

分析推论 重写系统时应把“供应商能力限制”“团队节奏偏好”和“作品风格”拆成不同配置；否则换模型或换片种时，人们容易直接改代码常量，却忘了这些数字背后的假设。

证据入口：novel-storyboard.mjs::DEFAULT_PARAMS、paramsOf()；references/storyboard-pass.md 第 5–29 行。

六、h3Prompt：把多张关键帧钉到段内时间线上

源码实现 对每个 segment，cutStarts() 从 0 开始累计前面 cut 的秒数。例如 3、4、3 秒三切的起点是 0、3、7。h3CutTime() 把起点格式化成 00:03.000；h3AlignmentLine() 再把 Picture 1..N 与这些时刻组成必须逐字匹配的首行。

1

图片对齐首行

单切使用固定 I2VA 句式；多切逐张写 Picture k 对齐第几秒。

2

视听描述

文档声明 [Shot 1] 起；文档要求第 2 切以后用自己的累计切点开行。源码实现 当前门只确认对应 marker 在 H3 正文中出现，没有证明它位于行首；每切运镜词则会在自己的 Shot 切片里检查。

3

整体音景

overall_soundscape 写环境、动作与非语言人声；画面动作改变时也要同步。

4

非叙事配乐

non_diegetic_music 写观众听见、角色听不见的配器与速度；无则 N/A。

源码实现 每个被 cut 认领的台词必须逐字出现在 <d>[标签] …</d> 块中；正则接受任意非空方括号标签，并不限定必须是 [Chinese]。语言检查先从 H3 中剔除 <d> 块和同一行双引号内容：promptLang === "en" 时，剩余正文出现 CJK 才失败；任何非 en 值都走中文 token 回退，只要求剩余正文至少有一个 CJK，不阻止中英混写，也不校验枚举。每个 frame 无论 H3 语言如何都必须非空且不含 CJK。

文档声明 说话人的身份、音色、语气写在 <d> 外；VO 另写画外音与闭唇指令。声景不是纯后期备注：文档把它视为可能驱动画面动作的生成指令。

两个时间轴：全片时间与段内时间

源码实现 每个 segment 都是独立生成单元，因此它自己的 Picture 1 永远钉在 0.00 秒，后续 cut 起点也只在本段内累计。跨三个段的 29 秒场次，H3 会拥有三条各自从零开始的局部时间线，而不是一条连续的 0–29 秒提示。

分析推论 后续剪辑或编排器必须另行保存“段在整集中的全局起点”。当前 manifest 记录段内 cutStarts 和段时长，却没有给段写全局 timecode。

证据入口：novel-storyboard.mjs::cutStarts()、h3CutTime()、h3AlignmentLine()、h3CutSlices() 与 gateReport() 的 H3 分支；references/h3-prompt.md。

七、17 道门：每道只拦可机械证明的违规

源码实现 gateReport() 固定返回下列 17 个稳定 gate id。validateStoryboard() 先做基本结构检查，再把未通过的门转成问题列表。CLI 要求提供 script；缺少 outline/cast 只跳过人名相关证据，缺配方库只跳过第 17 门。

表 3　gateReport() 的 17 个门及其证明范围
# / gate id 检查什么 需要什么证据 它不能证明什么
1 · coverage同一剧本场的每个 flow 位置被恰好一次、按顺序、连续认领；segment 的场次顺序不倒退。script + sceneIndex/beats不能证明覆盖镜头就是最佳视角。
2 · segment-cap每段 cut 秒数总和大于 0 且不超过 maxSegmentSeconds。storyboard params/cuts不能证明目标视频模型真的支持该时长。
3 · cut-length每切落在 minCutSeconds..maxCutSeconds。cut seconds不能证明节奏适合此处情绪。
4 · dialogue-fit被认领台词的估算秒数之和不大于 cut 秒数。script flow + 语速参数不能证明演员实际能自然说完。
5 · ep-duration整集所有段总时长在 script 目标的容差内。script targetSeconds不能用单场切片冒充整集通过。
6 · crowd画内人物不超阈值；超出时 cut 或 segment 必须有 note。cut characters/notenote 的拆解是否真正可生成仍要人看。
7 · segment-id段号精确等于 E{集号}-{顺序号}，集内连号。episode/curr index不提供跨版本稳定身份。
8 · size-phrasesize 在五档枚举内，且对应英文短语出现在 frame。cut size/frame不能检查生成图片实际景别。
9 · camera-phrasecamera 属于词表，且出现在自己的 H3 Shot 段落。cut camera/h3Prompt不能证明运镜合理或可实现。
10 · h3-structure首行由 cuts 推导后逐字一致；三个核心字段齐全有序；第 2 切起的时刻正确。cuts/h3Prompt/promptLang不能证明自然语言描述有美感。
11 · h3-dialogue认领的每句台词逐字进入 <d> 块。script flow/h3Prompt不能证明声线、口型或表演正确。
12 · h3-langen 拒绝剔除台词块与双引号内容后仍含 CJK 的正文；其他值使用中文 token，并只要求剩余正文至少含一个 CJK。promptLang/h3Prompt不校验 promptLang 枚举、不阻止中英混写，也不是完整语言识别。
13 · style-phrasestyle 在预设内，每条 frame 含同一预设英文短语。style/frame字符串一致不等于画面真的统一。
14 · prompt-english每条 frame 非空且不含 CJK。frame不验证英文语法或提示质量。
15 · prompt-no-namesframe 禁 outline/cast 人名；英文 H3 正文也禁人名。无 outline/cast 时显式跳过姓名库部分。可选 outline/cast无法识别没列入上游的别称。
16 · refs集与 sceneIndex 存在；cut 人物、道具是 script 该场集合子集。script不直接对账 art，因为合法集合已经由 script 承接。
17 · shot-recipe挂卡库时：配方 ID 存在、必备短语进入 frame、多格配方连续使用达到下限。可选 --shots 目录建议景别/运镜只提示偏离，不设硬门。

测试约束 selftest 直接断言 gateReport(...).length === 17，并为覆盖遗漏/重复、错误时长、H3 切点、语言、配方缺失等分支构造失败夹具；它还断言不给上游时相应门以带“跳过”说明的通过状态返回。

源码实现 validate/checkup 默认把每次运行和失败门追加到当前目录的 .gates.jsonl；stats 统计最常失败和从未失败的门。加 --no-log 可停记，写日志失败会被静默吞掉，不阻塞校验。

证据入口：novel-storyboard.mjs::gateReport() 第 419–675 行、validateStoryboard()、gateLogEntries()、summarizeGateLog() 与 CLI main()；scripts/selftest.mjs 的“质量门”“门失败累积”小节。

八、第 17 门为何是可选的：公开仓库没有完整卡库

源码实现 loadRecipes() 只读取指定目录顶层的 .md，以受限 frontmatter 解析 id/name/cuts/must_phrases/sizes/cameras 等机器字段。CLI 拒绝导出的 JSON，也会在目录不存在或没有卡片时直接报错，避免“用户以为挂上了，实际没生效”。

源码实现 挂库后，每个 cut 可有一个 recipe。must_phrases 以双方小写后的 includes 检查；卡片最小 cuts ≥2 时，同一 segment 内同 ID 必须连续出现足够多切。sizes 和 cameras 只由 recipeDrift() 产生报告提示，不使门失败。

文档声明 仓库内的迁移设计把完整 shot-recipes 迁往一个名为 shuohao-video-skills 的私有仓库作为目标；公开侧的合并提交与当前目录证明卡库已被清理，并以三张最小 fixture 保持分镜自测自包含。私有侧是否收到完整且当前的卡库不在本次审计范围。

测试约束 selftest 读取的正是 references/test-fixtures/shot-recipes 三张测试卡，覆盖未知 ID、缺必备短语、多格不够和建议偏离不设门；这些夹具证明接口行为，不代表完整私有镜头语汇库的内容。

资料缺口必须保持为资料缺口

分析推论 仅凭公开接口可以评估“卡如何被消费”，不能评估完整卡库的镜头分类、覆盖面、审美质量或授权状态。没有私有仓库访问权时，不应从卡名和三张测试夹具反推出全库。

重构建议 若你重做公开系统，可保留通用 recipe provider 接口，同时提供一个公开、版本化的小型基础卡库；否则用户看到第 17 门，却无法获得其主要内容。

证据入口：novel-storyboard.mjs::parseCardFields()、loadRecipes()、recipeDrift()、loadShots()；docs/superpowers/specs/2026-08-21-shot-recipes-repository-migration-design.md；storyboard selftest 的配方卡小节。

九、图片与视频的边界：脚本准备订单，不替你生产视频

源码实现 manifest 是数组而不是带版本信息的对象；当前实现也不会把 recipe 带进投产包。测试约束 selftest 明确断言 export 结果中不出现 recipe，因为它被视为创作期语汇。

源码实现 computeStats() 还会按 sceneId|lighting 聚合“生成批次”，汇总涉及的 segments、人物和道具，供报告作为共用环境参考的顺场提示；这是清单分组，不是实际批量调用。

证据入口：references/frame.md；novel-storyboard.mjs::renderHtml() 第 1093–1165 行、exportPack()、computeStats()；selftest 的 exportPack 小节。

29 秒是场次切片，不是整集合格证明

源码实现 ep-duration 汇总该集所有 segment，与 script 的 targetSeconds 做 ±15% 对账。若本集目标 120 秒，只放这 29 秒会失败；只有把全剧本场次都切完，或把教学 script 的目标明确设为 29 秒，才能讨论整集门。

十一、这套模型为什么好用，又为什么不能直接当通用分镜主数据

表 6　设计收益、代价与重写时的处理
观察 收益 限制 重写建议
线性数组 源码实现 episode/segment/cut 都有清晰顺序，校验简单，投产包自然。 分析推论 没有分支、条件、回流或互动选项实体；同一集只能表达一条播放路径。 重构建议 在线性生成视图之外另建 story graph；每条路径再派生 segment 顺序。
位置认领 用 sceneIndex + [from,to] 就能精确查漏、重复和顺序。 插场、插拍和重排会改变后续位置；旧镜头意图不能自动迁移。 给 scene occurrence 与 flow beat 稳定 ID，再把位置当构建产物。
恰好一次覆盖 非常适合“一个节拍只生成一次主画面”的线性 AI 视频订单，预算清楚。 同一句台词不能原生同时挂说话者、听者反应和主镜头安全覆盖；重复认领会失败。 用多对多 ShotBeatLink 保存拍摄覆盖，再派生一个不重叠的主剪版本。
一个 cut 一套 size/camera 枚举可机械校验，能直接写进 frame/H3。 复杂镜内调度、复合运镜或备用机位只能压进自然语言，结构层看不见。 保留 cut 主摄影意图，并用可选 camera phase / coverage take 扩展，而非把所有复杂度塞进字符串。
H3 内嵌核心数据 生成订单直接可复制；切点与台词有强对账。 供应商格式与领域主数据绑在一起；改视频模型要重写每段长字符串。 将动作、对白、声音、音乐、参考图和切点结构化，再由 H3 adapter 生成提示。
字符串质量门 能拦缺字段、缺短语、错误语言和错切点，成本低且确定。 短语存在不等于图片符合；合法提示也可能单调、冲突或不可生成。 保留结构门，再加可选图像/视频结果 QC；不要把结果质量伪装成文本门已覆盖。
sceneIndex 反查 storyboard 不重复存 sceneId/lighting/完整 flow，减少当前文件内冗余。 脱离同版本 script 后，storyboard 难以独立解释；script 场次重排即改变指向。 保存稳定 occurrenceId，并在导出清单中冗余可核验的 sceneId 与 source revision。
可选私有配方 分镜核心不依赖卡库，公开仓库仍可自测。 公开仓库不提供完整镜头语汇；用户未自行提供兼容卡库时，第 17 门会跳过。 把卡库作为明确版本的插件依赖，并公开最小基线或提供能力探测。
投产止于 manifest 责任边界清楚，任何视频供应商都可在后面接 adapter。 当前仓库没有生成状态、失败重试、视频文件 provenance、剪辑拼接或口型同步。 新增独立 production-run 层，不把远端任务状态塞回创作 storyboard。

最重要的判断

分析推论 shuohao storyboard 是一份很强的单一路径 AI 视频生成规格：它对节拍覆盖、时长、提示词和参考图订单的纪律，远强于只写“镜号 + 画面”的松散表格。但它不是完整的影视分镜领域模型，也不是视频生产系统。

重构建议 最合理的继承方式不是推翻它，而是把它放在统一主数据之后：稳定场次/节拍/镜头关系负责长期编辑，shuohao adapter 负责把一条批准路径压成 segment、cut、H3 和 manifest。
